# Воспроизведение расчётов статьи «Метод оценки целостности цепочки сборки и обновления программного обеспечения на основе графа доказательств»

Редакция для журнала «Вопросы кибербезопасности». Пакет пересчитывает все расчётные числа статьи по формулам (1)–(4). Это числа разделов «Вероятностная интерпретация индекса» и «Результаты исследования и их обсуждение», в том числе табл. 2, 3 и 5. Нужен только Python 3.8 или новее, сторонние пакеты не используются.

Пакет входит в репозиторий https://github.com/alexqzm/scii-gate (каталог `paper/evidence-graph-method`, DOI 10.5281/zenodo.23833592). Расчёт не импортирует модуль допуска `scii/model.py` и реализует формулы статьи отдельно, поэтому сверка с результатами гейта служит перекрёстной проверкой.

## Файлы

| Файл | Содержание |
|---|---|
| `profile.json` | Демонстрационный профиль политики из раздела «Результаты исследования и их обсуждение». В нём граф, классы рёбер и их коды, порог θ, каталог свидетельств с весами α и обязательными свидетельствами, записи сценариев 1–4, параметры графа со сходящимися путями и случайной проверки. В поле `real_chain` 16 сценариев прогона стенда ArduPilot с разметкой «опасный» или «штатный», эталонный сценарий и порог. |
| `scii_repro.py` | Расчёт по формулам статьи. |
| `expected_output.txt` | Вывод команды `python3 scii_repro.py --check`. |

## Команды

```
python3 scii_repro.py                     # табл. 2, 3, 5 и остальные числа статьи
python3 scii_repro.py --check             # то же и сверка с числами статьи, код возврата 0 при совпадении
python3 scii_repro.py --json results.json # все результаты в JSON
```

Расчёт занимает около секунды.

## Соглашения

- Состояние свидетельства обозначается так. P означает «подтверждено» (a = 1, z = 1), N «отсутствует» (a = 0), F «опровергнуто» (a = 1, z = 0). В `profile.json` для каждой записи перечислены отсутствующие и опровергнутые свидетельства, остальные подтверждены.
- Окрестность N(w) содержит саму функцию w и 7 функций, в которых класс одного ребра сдвинут на соседний класс шкалы. Всего 8 элементов.
- Ящик B(w) содержит 54 набора, в которых класс каждого ребра остаётся прежним или сдвигается на соседний. Индекс не возрастает по весу каждого ребра, поэтому его крайние значения на ящике достигаются в двух угловых наборах (все классы на шаг выше или ниже). Программа проверяет это перебором всех 54 наборов.
- Порог по процедуре из абзаца «Назначение профиля» равен R_P^min эталонной записи, округлённому вниз до 0,001.
- Правило (4) сравнивает границы индекса с порогом с абсолютным допуском 10^-9, как модуль допуска `scii/model.py` (константа `THETA_TOL`). Индекс считается в плавающей арифметике, и значение, равное порогу в точной арифметике, может отличаться от него на ошибку округления: R_P^min эталона стенда 0,4968 вычисляется как 0,4967999999999999. С допуском граница допуска остаётся включённой. Решение отличается от строгого сравнения, только если граница индекса отстоит от порога меньше чем на 10^-9.
- Строки с пометкой «дополнительно» в выводе `--check` проверяют числа, которых нет в тексте статьи.

## Варианты контролируемого эксперимента (табл. 3)

Эталонная запись содержит все 17 свидетельств каталога в состоянии P. В каждом из 34 случаев одно свидетельство переводится в N или F.

| Вариант | Правило решения |
|---|---|
| Бинарный контроль | Допуск при B_P = 1, иначе отказ. |
| Бинарный контроль с обязательной пересборкой | Допуск при B_P = 1 и подтверждённой независимой пересборке (s24), иначе отказ. |
| Аддитивный индекс | Правило (4), в котором R_P^min и R_P^max заменены средним меток ℓ_A(v) по вершинам. Среднее считается в рациональной арифметике, чтобы сравнение на границе порога не зависело от округления. |
| Графовый индекс без блокирующего условия | Допуск при R_P^min ≥ θ, отказ при R_P^max < θ, иначе ручное рассмотрение. G_P и B_P не проверяются. |
| Полный метод | Правило (4). |

Индексные варианты считаются при общем пороге 0,75 и при калиброванном. Калиброванный порог равен наименьшему значению индекса сценария 1 в данном варианте, округлённому вниз до 0,001. Для аддитивного индекса это 0,940, для графовых вариантов 0,776.

## Анализ чувствительности

- Сдвиг класса одного ребра на соседний, 7 комбинаций (дополнительно).
- Сдвиг классов любого непустого подмножества рёбер, 53 комбинации.
- Все 84 строго возрастающих набора кодов слабого, среднего и сильного классов с шагом 0,1 от 0,1 до 0,9 при коде критического класса 1,0. Они дают 7 разных векторов весов рёбер примера.
- Ящик B(w) для сценариев 1 и 2 и правило (4) с ящиком при θ = 0,75.
- Веса свидетельств: 35 переносов 0,1 между двумя свидетельствами одной вершины и уравнивание весов в каждой вершине, всего 36 вариантов. Для каждого варианта решение сценария 1 считается при постоянном пороге 0,75, а решение сценария 2 при пороге, назначенном по процедуре для того же набора весов.

## Граф со сходящимися путями (раздел «Вероятностная интерпретация индекса», рис. 1, б)

Точная вероятность Pr[I = 1] вычисляется перебором всех 2^8 исходов модели (6) при предположениях П1–П3. Нарушения проверяются по неравенству (7). В случайной проверке метки и веса выбираются независимо и равномерно на [0, 1] и округляются до 0,001. Используется генератор Python `random` с начальным значением 20240628, вызовы идут в порядке d1–d4, затем рёбра в порядке `profile.json`.

## Реальная цепочка и политики (табл. 5)

Записи взяты из прогона стенда 30.10.2026: файл `results/results.json` репозитория scii-gate, все 16 сценариев. Состояния свидетельств установил модуль допуска по артефактам сборки ArduPilot Copter-4.5.7 для CubeOrange. Подписи и аттестации ролей поставщика стенд создал тестовыми ключами. Ожидаемые решения программы испытаний вычислены той же моделью, поэтому прогон проверяет прежде всего проверки свидетельств модуля. Граф, классы рёбер и веса α совпадают с демонстрационным профилем, меняется только порог. Эталон стенда (B1) демонстрационный: это полная запись, достижимая на стенде. Для эксплуатации эталон утверждает владелец политики по требованиям конкретной системы.

Разметка «опасный» взята из программы испытаний, записанной до прогона: группа A (атаки и нарушения порядка выпуска, 9 сценариев) опасна, группы O (официальный выпуск) и B (цепочка поставщика) штатные, всего 7. Разметка задана замыслом сценариев и от решений модели не зависит.

Пороги назначены по эталонному сценарию B1 той же процедурой. Для полного метода и графового индекса без блокирующего условия это θ = 0,496 (R_P^min эталона 0,4968), для аддитивного индекса 0,840, для профиля с ящиком B(w) 0,270. Табл. 5 для каждой политики и каждой группы (9 опасных и 7 штатных сценариев) считает допуски, отказы, ручные рассмотрения и запросы свидетельств. Сценарии B3 (штатный сборщик без независимой пересборки) и A5b (скомпрометированный сборщик без неё) дали одинаковые состояния.

Программа также находит в рациональной арифметике полуинтервал порога, на котором решения всех 16 сценариев не меняются: 0,46512 < θ ≤ 0,4968. Решение правила (4) меняется только там, где порог проходит R_P^min записи с B_P = 1 или R_P^max записи с G_P = 1, поэтому границы равны R_P^min записи без пересборки (B3 = A5b) и эталона. На сетке с шагом 0,001 это значения от 0,466 до 0,496. Кроме того, программа пересчитывает решения при 36 вариантах весов α с постоянным порогом 0,496 и с порогом, назначаемым по эталону для каждого набора весов.

Совпадение записей пакета с результатами прогона и совпадение решений пакета с расчётом `scii/model.py` проверяет тест `tests/test_paper_evidence_graph_method.py` репозитория.
