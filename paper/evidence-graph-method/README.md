# Воспроизведение расчётов статьи «Метод оценки целостности цепочки сборки и обновления программного обеспечения на основе графа доказательств»

Редакция для журнала «Вопросы кибербезопасности». Пакет пересчитывает все расчётные числа статьи по формулам (1)–(4). Это числа разделов «Вероятностная интерпретация индекса» и «Результаты исследования и их обсуждение», в том числе табл. 2, 3 и 5. Нужен только Python 3.8 или новее, сторонние пакеты не используются.

Пакет входит в репозиторий https://github.com/alexqzm/scii-gate (каталог `paper/evidence-graph-method`, DOI 10.5281/zenodo.23833592). Расчёт не импортирует модуль допуска `scii/model.py` и реализует формулы статьи отдельно, поэтому сверка с результатами гейта служит перекрёстной проверкой.

## Файлы

| Файл | Содержание |
|---|---|
| `profile.json` | Демонстрационный профиль политики из раздела «Результаты исследования и их обсуждение». В нём граф, классы рёбер и их коды, порог θ, каталог свидетельств с весами α и обязательными свидетельствами, записи сценариев 1–4 и записей 5 и 6, параметры ромбовидного графа и случайной проверки. В поле `real_chain` записи реальной цепочки ArduPilot (табл. 5) и её порог. |
| `scii_repro.py` | Расчёт по формулам статьи. |
| `expected_output.txt` | Вывод команды `python3 scii_repro.py --check`. |

## Команды

```
python3 scii_repro.py                     # табл. 2, 3, 5 и остальные числа раздела «Результаты…»
python3 scii_repro.py --check             # то же и сверка с числами статьи, код возврата 0 при совпадении
python3 scii_repro.py --json results.json # все результаты в JSON
```

Расчёт занимает меньше секунды.

## Соглашения

- Состояние свидетельства обозначается так. P означает «подтверждено» (a = 1, z = 1), N «отсутствует» (a = 0), F «опровергнуто» (a = 1, z = 0). В `profile.json` для каждой записи перечислены отсутствующие и опровергнутые свидетельства, остальные подтверждены.
- Окрестность N(w) содержит саму функцию w и 7 функций, в которых класс одного ребра сдвинут на соседний класс шкалы. Всего 8 элементов.
- Пороговое решение означает условие R_P(A) ≥ θ без учёта окрестности N(w).
- Порог по процедуре из абзаца «Назначение профиля» равен R_P^min эталонной записи. Эталон задан полем `threshold_reference_record`.

## Варианты контролируемого эксперимента (табл. 3)

Эталонная запись содержит все 17 свидетельств каталога в состоянии P. В каждом из 34 случаев одно свидетельство переводится в N или F.

| Вариант | Правило решения |
|---|---|
| Бинарный контроль | Допуск при B_P = 1, иначе отказ. |
| Аддитивный индекс с тем же блокирующим условием | Правило (4), в котором R_P^min и R_P^max заменены средним меток ℓ_A(v) по вершинам. |
| Графовый индекс без блокирующего условия | Допуск при R_P^min ≥ θ, отказ при R_P^max < θ, иначе ручное рассмотрение. G_P и B_P не проверяются. |
| Полный метод | Правило (4). |

## Анализ чувствительности

- Вариант (а): класс одного ребра сдвинут на соседний, 7 комбинаций.
- Вариант (б): классы любого непустого подмножества рёбер сдвинуты на соседние, 53 комбинации.
- Вариант (в): все 84 строго возрастающих набора кодов слабого, среднего и сильного классов с шагом 0,1 от 0,1 до 0,9 при коде критического класса 1,0.
- Ошибка в классах всех рёбер сразу: 54 набора, в которых класс каждого ребра остаётся прежним или сдвигается на соседний. Индекс не возрастает по весу каждого ребра, поэтому его крайние значения достигаются в двух угловых наборах. Программа проверяет это перебором всех 54 наборов.
- Веса свидетельств: 35 переносов 0,1 между двумя свидетельствами одной вершины и уравнивание весов в каждой вершине, всего 36 вариантов.

## Ромбовидный граф (раздел «Вероятностная интерпретация индекса», рис. 1, б)

Точная вероятность Pr[I = 1] вычисляется перебором всех 2^8 исходов модели (6) при предположениях П1–П3. Нарушения проверяются по неравенству (7). В случайной проверке метки и веса выбираются независимо и равномерно на [0, 1] и округляются до 0,001. Используется генератор Python `random` с начальным значением 20240628, вызовы идут в порядке d1–d4, затем рёбра в порядке `profile.json`.

## Реальная цепочка (табл. 5)

Записи взяты из прогона стенда 30.10.2026: файл `results/results.json` репозитория scii-gate, сценарии O1, B1, B3, A5b, A5a, A3, A2, A6 и B5a. Сценарии O1, B1, B3, A5b и A5a дают табл. 5, A3 и A2 упомянуты в абзаце после неё, A6 и B5a в «Ограничениях». Состояния свидетельств установил модуль допуска по артефактам сборки ArduPilot Copter-4.5.7 для CubeOrange. Подписи и аттестации ролей поставщика стенд создал тестовыми ключами. Ожидаемые решения программы испытаний вычислены той же моделью, поэтому прогон проверяет прежде всего проверки свидетельств модуля. Граф, классы рёбер и веса α совпадают с демонстрационным профилем, меняется только порог. Порог θ = 0,496 равен R_P^min эталонной записи (0,4968), округлённому вниз до 0,001, как записано в программе испытаний до прогона. Сценарии B3 (штатный сборщик без независимой пересборки) и A5b (скомпрометированный сборщик без неё) дали одинаковые состояния и занимают в табл. 5 одну строку. Пакет пересчитывает индекс, интервал, блокирующее условие и решение по этим состояниям. Совпадение состояний с результатами прогона проверяет тест `tests/test_paper_evidence_graph_method.py` репозитория.
